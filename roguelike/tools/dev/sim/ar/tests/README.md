## Harness
Vendored copies of scratchpad az/tests_cm/lib (cmsim -> azsim -> fgsim -> mcsim), identical in `lib/` and `../s3/lib/`.
I1 / S5 extensions (real game features only): typed SNBT arrays `[I;..]`, `execute summon <type>`, the NBT path grammar (`[{..}]` list filters, `[-n]`, `[]`, `key{..}`) in data get / set / remove / `if data` (cmsim's own path parser defers to it). Known gap: integer `summon` / `tp` coordinates are not centre-corrected (+0.5) as in game.
Since I1 the module suites run here too: `test_arlecchino.py`, `pat_p1.py`, `pat_p2.py` (on `../s3/lib/knsim.py`), `kit_dry.py`, `test_rig.py --dp <dp> --rp <rp>`; balance probes `../review/bal/` (knfair5.py: knfair2 + an orb-collecting agent, the real healorb tick, the engine's normal-attack flag).

`lib/knsim.py` (S1) adds `variant_ar(dp, route)`: a cmsim variant tree (generated folders and tools/ copied, the rest
hard links, under `tmp/`, removed after use) with the D0 `arlecchino` entry forced on (`enabled:true`, `route` as asked),
regenerated by core / arena / cboss rooms. While S3's module is not in the tree, a **stub module** is written into the
copy (`F:boss/arlecchino/**`: the 17 hooks + prep + test/help; a husk body through `mboss/cb/body`, a 20-t intro, the
phase-1 floor, then repool 36 % / title / music 2; test ids 10 lose, 11 floor hit); it exercises the framework only and
is never part of a tree. With S3's module present (I1 on) the variant uses the real module and the stub-only checks are
skipped. Sim limits worked around: cproto ends any cine of its own when its clock is 0 (the cine checks hold `#cpCine`);
the dash i-frames are set right before each hit (as test_fw_ap); `test/chapter_ch` refuses inside a run (`#active 0`).
